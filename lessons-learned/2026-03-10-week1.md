## 1. `debug ip packet` on a live router — never without a filter

**What happened:**  
Ran `debug ip packet` on the Cisco 891F to troubleshoot a routing issue. The console was immediately flooded with thousands of lines per second — every packet traversing the router was logged. The SSH session froze and became unresponsive.

**Root cause:**  
The router was actively handling NAT, DNS forwarding, and inter-VLAN traffic. Without an ACL filter, `debug ip packet` captures everything.

**Fix:**  
Killed the session, reconnected via console, ran `undebug all`.

**Correct approach:**  
Always filter debugs with an ACL before running:
```
access-list 199 permit ip host 10.0.10.5 any
debug ip packet 199
```
Never run unfiltered packet debugs on a live device.

## 2. `no ip domain-lookup` breaks the router's own DNS resolution

**What happened:**  
Added `no ip domain-lookup` to stop the router from hanging on mistyped commands (Cisco interprets unknown commands as hostnames and tries to resolve them via DNS — very annoying). This worked as intended but also broke the router's own ability to resolve names for NTP, outbound connections, and hostname-based routes.

**Root cause:**  
`no ip domain-lookup` disables ALL DNS resolution on the device — not just the console behaviour.

**Fix:**  
Re-enabled with `ip domain-lookup` and accepted the minor annoyance of the lookup delay on typos.

**Lesson:**  
In a lab environment, keep `ip domain-lookup` enabled. The hanging on typos is a minor inconvenience. Breaking your own infrastructure's name resolution is worse.

## 3. VLANs on IOS 12.2 are stored in `vlan.dat` — not in `startup-config`

**What happened:**  
Configured VLANs on the Cisco 3560-CG, saved with `write memory`, reloaded the switch. All VLANs were gone. Had to recreate them from scratch.

**Root cause:**  
On IOS 12.2 (and many older Catalyst platforms), VLAN information is stored separately in `vlan.dat` on flash — not in the running/startup config. `write memory` saves the startup config but does NOT save `vlan.dat`.

**Verification:**  
Always run `show vlan brief` after a reload to confirm VLANs persisted.

**Lesson:**  
On IOS 12.2 devices, treat VLANs as a separate entity from the main config. Monitor after every reload. This is fixed in later IOS versions where VLANs are integrated into the config.

## 4. Native VLAN must match on both trunk endpoints

**What happened:**  
Configured VLAN 999 as the native VLAN on the 891F trunk interface but initially left the 3560-CG at the default native VLAN 1. The trunk came up but traffic was unreliable and some VLANs dropped intermittently.

**Root cause:**  
Native VLAN mismatch on a 802.1Q trunk causes untagged frames to be assigned to different VLANs on each end. CDP/STP will report a native VLAN mismatch warning.

**Fix:**  
Set `switchport trunk native vlan 999` on both ends. Verified with `show interfaces trunk`.

**Lesson:**  
Always configure native VLAN explicitly on both sides of every trunk. Never rely on defaults.

## 5. ISP routes through RFC1918 space and blocks some public DNS

**What happened:**  
After configuring NAT and getting internet connectivity, tested DNS with multiple servers. 8.8.8.8 (Google primary) worked. 8.8.4.4 (Google secondary) was unreachable. 1.1.1.1 (Cloudflare) worked.

**Root cause:**  
ISP (Telia/Allente) internally routes traffic through RFC1918 address space (172.21.x.x observed) and blocks certain public DNS servers at the network edge. This is not uncommon with Swedish residential ISPs.

**Impact:**  
DHCP pool DNS configuration had to use only verified-working servers:
```
dns-server 8.8.8.8 1.1.1.1
```

**Lesson:**  
Never assume all public DNS servers are reachable. Test explicitly from behind the NAT after setup. Also explains why anti-spoofing ACLs blocking RFC1918 inbound need to be carefully scoped — the ISP itself uses these ranges.

## 6. Ubuntu 24.04 DNS with NetworkManager renderer does not persist via `nmcli` alone

**What happened:**  
Set DNS on the T470s PAW using `nmcli con mod` to point to DC01 (10.0.20.2). DNS worked immediately. After reboot, DNS reverted to 127.0.0.53 (systemd-resolved stub).

**Root cause:**  
When netplan uses `renderer: NetworkManager`, DNS settings need to be defined in the netplan YAML file — not just applied via `nmcli`. The nmcli change was applied to the active connection but not persisted to the netplan configuration layer.

**Fix:**  
Edited `/etc/netplan/01-network-manager-all.yaml` to include:
```yaml
network:
  version: 2
  renderer: NetworkManager
  ethernets:
    enp0s31f6:
      dhcp4: true
      nameservers:
        addresses: [10.0.20.2, 8.8.8.8]
```
Then ran `sudo netplan apply`. Verified persistence with full reboot.

**Lesson:**  
On Ubuntu with NetworkManager renderer, always configure DNS in the netplan YAML. Verify with a full reboot — not just a service restart. Use `resolvectl status | grep DNS` to confirm.

## 7. Always `wr` immediately — NVRAM is the only persistence

**What happened:**  
Made several incremental changes to the 891F and 3560-CG during a session without saving. A power fluctuation (brief, stable Swedish grid 😄) caused an unexpected reload. Lost ~30 minutes of config work.

**Lesson:**  
`write memory` (or `wr`) after every meaningful change. No exceptions. In a lab environment there is no automatic save, no rollback, no config management agent. NVRAM is it.

**Habit formed:**  
Every config session ends with `wr` and a `show running-config` spot check before disconnecting.

---

## 8. Migrate services during a planned window — even in a homelab

**What happened:**  
Migrated DC01 from the home LAN (192.168.0.50) to the lab network (10.0.20.2) while actively using it for DNS. Caused a brief outage of DNS resolution and RDP access during the IP change.

**Lesson:**  
Even in a lab, treat service migrations as planned maintenance windows. Document the before/after state, have console access ready as a fallback, and test DNS/routing before cutting over. Good habits here translate directly to production discipline.

---

## 9. Document everything before you touch it

**Lesson formed over the week:**  
Every time something broke, the recovery was faster when the original state was documented. Serial numbers, current IPs, current configs, interface states — all of it.

This repo exists because of this lesson. Every config is committed before it's changed. Every IP is recorded before it's moved. Every VLAN is listed before the switch reloads.

The discipline of documentation is the discipline of engineering.
