## Lessons

### 1. iDRAC XML exports are a goldmine before you touch hardware

Parsing the iDRAC hardware inventory XML before opening a server saved significant time.  
Every DIMM slot, part number, speed, and manufacturer is recorded — no need to physically unseat each stick to read the label.  
**Takeaway:** Always export iDRAC/iLO inventory XML before any hardware change. Treat it as your pre-flight checklist.

### 2. Mixed DIMM speeds always throttle to the slowest stick

Both R620s now have a mix of 1333MHz and 1600MHz DIMMs. The memory bus runs at 1333MHz across the board — the faster DIMMs don't run at their rated speed.  
This is expected and unavoidable without a full matched set.  
**Takeaway:** For future RAM purchases, match speed across all slots. A matched 1600MHz set would recover ~5-10% memory bandwidth. Not critical for a homelab but worth knowing.

### 3. Slot population balance matters more than total capacity

The R620 has two CPUs, each with 12 DIMM slots. Running unbalanced across CPUs (e.g. 8 DIMMs on CPU1, 4 on CPU2) causes NUMA asymmetry and can hurt VM performance.  
After the swap, itc-uvy-prx-01 runs 6+6 (A-side: 6 × 8GB, B-side: 6 × 8GB) — perfectly symmetric.  
**Takeaway:** Always distribute DIMMs evenly across CPU channels. Dell's memory population guide for the R620 specifies the correct slot order (A1, B1, A2, B2…).

### 4. Printing a slot map before doing the swap is worth the 2 minutes

A printed per-server population diagram with colour-coded actions (keep/pull/install) removed all ambiguity during the physical swap. No second-guessing which slot to pull from.  
**Takeaway:** Generate a population reference sheet for any RAM work. Especially valuable in 1U/2U servers where slot labels are tiny and poorly lit inside a rack.

### 5. Always check BBU health after moving RAID controllers

The H710 Mini BBU on itc-uvy-esxi-01 was confirmed healthy after the swap. A RAID controller that loses its battery-backed write cache (BBU) silently downgrades to write-through mode, tanking write performance.  
**Takeaway:** After any server move or hardware change, verify BBU status in iDRAC → Storage. A degraded BBU can cut write performance by 30-50% with no visible warning to the OS.

### 6. Spare drives found = document immediately

3× SAS 300GB 10K and 1× SAS 600GB 10K 2.5" found on the bench. Both R620s support 2.5" hot-swap bays. These aren't fast enough for primary VM storage but are viable for backup targets, a dedicated logging volume, or a test RAID array.  
**Takeaway:** Inventory everything, even parts you're not using yet. Undocumented hardware gets forgotten.
